# Session 5.4 — Match Animation (Shake → Explode)

## Goal

Replace the placeholder `setMatched()` visual (session 3's simple scale/tint) with a real two-stage animation: both matched cards shake in place for at least 1 second, then explode outward off-screen and are removed from the board.

## Depends on

Session 3 (`Card` class), session 5 (`GameController` match handling). Supersedes the "match feedback" portion of session 8 (`08-polish-animations.md`) for the specific match animation — session 8 can focus on other polish (mismatch shake/color, entrance animation, win celebration) instead of re-doing this.

## Animation spec

1. **Shake stage (≥1000ms)**: both matched cards jitter — small rapid oscillation of position and/or rotation (e.g. ±0.03 units / ±3–5° on a couple axes, alternating direction every ~50–80ms) for a minimum of 1 second. Keep the shake readable as "these two matched" (consider a color/emissive pulse or glow tint added on top so it doesn't read as an error/mismatch shake if session 8 also adds a mismatch shake — the two should look distinct, e.g. matched = green-ish glow + gentle shake, mismatch = red-ish flash + shake, if both exist).
2. **Explode stage (~400–600ms)**: immediately after the shake, both cards animate rapidly outward and off the visible board — e.g. scale up while flying away from board center (or straight toward camera / off to a screen edge) combined with fade-out (opacity via material `transparent`/`opacity`, or scale to near-zero if fade is harder with the chosen material setup). End state: card mesh removed from the scene (or set invisible + removed from raycast targets) so it can't be tapped again and doesn't linger.
3. Both cards animate in sync (mirror or same timing), driven by the existing per-frame update mechanism from session 3 (`Card.update(deltaTime)` or equivalent) — no new animation library, hand-rolled tweening consistent with the rest of the project.

## Tasks

- Extend `Card` with an animation state machine addition: `idle → shaking → exploding → removed`, or a dedicated `playMatchAnimation(onComplete)` method encapsulating both stages and invoking a completion callback when the mesh is fully gone.
- Update `GameController`'s match-handling branch (from session 5): instead of calling the old `setMatched()` synchronously, call `card.playMatchAnimation(...)` on both cards and only mark them fully "done" (removed from raycast targets, counted toward win condition's *visual* completion) once the animation completes. Scoring (session 5.2) should still be computed and awarded at the moment of match detection — the animation shouldn't delay when points are earned, only when the cards visually leave the board.
- Decide and document how `locked` interacts with this: recommend keeping `locked = true` for the full shake+explode duration (mirroring how mismatches already lock), so a player can't start a third flip while the matched pair is still animating away. Unlock once both cards finish exploding.
- Win detection nuance: if the last pair in the board completes the game, wait for that pair's explode animation to finish before showing the win screen (avoids a jarring instant win-screen pop while cards are still mid-animation).

## Files touched

`src/game/Card.js` (animation methods/state), `src/game/GameController.js` (match branch updated to use the new async-ish animation + completion callback, `locked`/win-check timing).

## Done when

- Matching a pair visibly shakes both cards in place for at least a full second, then both cards rapidly scale/fly outward and fade/disappear from the board, leaving an empty gap where they were.
- Input is correctly blocked for a third card tap until the matched pair's full animation (shake + explode) has finished.
- Score/streak bonus (if session 5.2 is already in place) is awarded immediately on match detection, not delayed until the animation ends.
- Completing the final pair of a board waits for that pair's explode animation before the win screen appears.
