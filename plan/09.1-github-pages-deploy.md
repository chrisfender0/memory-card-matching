# Session 9.1 — GitHub Pages Deployment

## Goal

Get the built game live on GitHub Pages (e.g. `chrisfender0.github.io` or `chrisfender0.github.io/<repo-name>`), deploying automatically on push.

## Depends on

Session 1 (Vite project), session 9 (production build verified working when statically served).

## Decide up front

- **User page** (`chrisfender0.github.io`, repo literally named `chrisfender0.github.io`): site is served from the repo root URL, no base path needed.
- **Project page** (any other repo name, served at `chrisfender0.github.io/<repo-name>`): needs a `base` path configured or all asset URLs will 404.

Confirm which of these applies before starting (repo name decides it).

## Tasks

- **Vite base path** (project-page case only): in `vite.config.js`, set `base: '/<repo-name>/'`. Skip/leave default (`/`) for the user-page case.
- **Router/asset paths check**: since this is a single-page app with no client-side router, this mostly just affects how Vite emits `<script>`/asset URLs in the built `index.html` — verify `npm run build` output references `/<repo-name>/assets/...` correctly (project-page case) by checking `dist/index.html`.
- **GitHub Actions workflow** (`.github/workflows/deploy.yml`): on push to `main` (or chosen default branch), run `npm ci`, `npm run build`, then deploy `dist/` using the standard GitHub Pages Actions flow:
  - `actions/configure-pages@v5`
  - `actions/upload-pages-artifact@v3` pointing at `dist`
  - `actions/deploy-pages@v4`
  - Needs `permissions: pages: write, id-token: write` and the `github-pages` environment in the job.
- **Repo settings**: under Settings → Pages, set Source to "GitHub Actions" (not "Deploy from a branch") so the workflow above is what serves the site.
- **404 handling**: since this is a single static page with no routes, no special 404→index rewrite is needed (that's only a concern for client-side-routed multi-page apps). Skip unless a router gets added later.
- **Verify**: push to `main`, confirm the Actions run succeeds, and load the live URL (`https://chrisfender0.github.io/` or `https://chrisfender0.github.io/<repo-name>/`) to confirm the game loads, textures render, and localStorage-based leaderboard/reset (sessions 5.1/5.3) work on the live domain.

## Files touched

`vite.config.js` (base path, if project-page), `.github/workflows/deploy.yml` (new).

## Done when

- A push to the default branch triggers a successful Actions deploy with no manual steps.
- The live GitHub Pages URL loads the game correctly (assets resolve, no 404s in console), on both desktop and a mobile device/emulation.
- Leaderboard, name persistence, and reset-data (sessions 5.1/5.3) work correctly against the live URL's origin.
