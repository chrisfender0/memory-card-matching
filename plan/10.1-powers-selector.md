# Session 10.1 — Powers Selector (Swipeable Carousel)

## Goal

Build the actual power-selection UI that appears when "Special Powers" is toggled on: a swipeable, one-at-a-time carousel showing each power's icon, name, and description, with a clear way to confirm a choice.

## Depends on

Session 10 (toggle, `GameSession.powersEnabled`/`selectedPowerId`, `registry.js` — can build/test against a couple of placeholder entries even before 10.2's real power icons/copy exist).

## Tasks

- Replace the placeholder slot from session 10 with a real carousel component, e.g. `src/ui/screens/PowerSelector.js`.
- **Markup**: a horizontally scrollable row of "power cards" (one per `POWERS` registry entry), each showing: icon (image/canvas from session 10.2), power name, short description text.
- **Swipe mechanics**: use native scrolling + CSS scroll-snap rather than a JS gesture library (keeps dependencies at zero) —
  - Container: `overflow-x: auto; scroll-snap-type: x mandatory; -webkit-overflow-scrolling: touch;` with `scrollbar-width: none`/`::-webkit-scrollbar { display: none }` to hide the scrollbar.
  - Each item: `scroll-snap-align: center`, sized to roughly one item per viewport width (with a peek of neighbors on either side, e.g. `flex: 0 0 80%`) so swiping feels like a carousel.
- **Non-touch support**: left/right arrow buttons that call `scrollBy({ left: itemWidth, behavior: 'smooth' })`, for desktop/mouse testing.
- **Pagination indicator**: small dots below the carousel reflecting the currently centered item — track via `scroll` event + `IntersectionObserver` (or a simpler scroll-position → index calculation) to know which item is centered.
- **Selection confirmation**: don't select purely from a stray tap mid-swipe. Recommended pattern: swiping only changes which item is *centered/previewed*; a persistent "Select This Power" button below the carousel confirms the centered item into `GameSession.selectedPowerId` (and visually marks that card as selected, e.g. border/glow). Re-centering on a different item before confirming just changes the preview, no state change yet.
- Play button on the setup page (from session 5.1/10) becomes enabled once a power is confirmed (when the toggle is on) — same gating rule as session 10 already set up, just now satisfiable.
- Toggling "Special Powers" off should clear `selectedPowerId` and hide the carousel; toggling back on should require re-confirming (no stale selection carried over silently).

## Files touched

`src/ui/screens/PowerSelector.js` (new), `src/ui/screens/Setup.js` (mount/unmount the selector based on toggle state), `src/style.css` (carousel, snap, dots, selected-state styling).

## Done when

- With the toggle on, the carousel renders one card per registry entry, swipes smoothly by touch (test via devtools touch emulation or a real device) and via the arrow buttons, and the dot indicator tracks the centered item correctly.
- Tapping "Select This Power" confirms the centered card, visually marks it selected, and enables Play; changing the centered item afterward doesn't silently change the selection until "Select This Power" is tapped again.
- Turning the toggle off clears the selection and hides the carousel; turning it back on requires choosing again.
- Works correctly with however many entries currently exist in `POWERS` (don't hardcode assumptions about exactly 6 — session 10.2 fills the registry, but this component shouldn't need changes when it does).
