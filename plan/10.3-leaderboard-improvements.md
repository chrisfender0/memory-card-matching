# Session 10.3 — Leaderboard Improvements

## Goal

Make the leaderboard richer: tap an entry for details, toggle between regular and special-powers scores, filter by which power was used, and show a small power icon per entry.

## Depends on

Session 5.1 (`src/storage/leaderboard.js`, landing page leaderboard list), session 5.2 (scoring/`moves` tracking), session 10 (`GameSession.powersEnabled`/`selectedPowerId`), session 10.2 (`generatePowerIcon(id)` for the small per-entry icons).

## Data model changes

Extend the leaderboard entry shape saved by `addScore()` (session 5.1) with the fields this session needs:

```
{
  name: string,
  score: number,
  level: "easy" | "medium" | "hard",
  date: ISOString,          // already existed
  durationSeconds: number,  // time taken to finish (2:00 minus secondsRemaining at win, or elapsed time)
  moves: number,            // total moves/turns taken (already tracked by GameController)
  highestMatchPoints: number, // the single highest-scoring match in that game (base + any bonus/multiplier for that match)
  powerId: string | null,   // id of the power used, or null if powers were off
}
```

- Wherever the win/game-over screen (session 7) currently calls `addScore()`, it now needs to pass these extra fields — track `highestMatchPoints` in `ScoreController` (session 5.2) as a running max updated every time `recordMatch()` awards points, and expose it (e.g. `scoreController.highestMatchPoints`) for the win screen to read at game end.
- Keep `getLeaderboard()` backward-tolerant: entries saved before this session won't have these fields — default missing values sensibly (e.g. `moves: 0`, `powerId: null`, `highestMatchPoints: 0`) rather than crashing the detail view or filters.

## Entry detail view

- Tapping/clicking a leaderboard row expands (or opens a small modal/overlay) showing: date (formatted, e.g. "Jul 31, 2026, 3:42 PM"), time taken (`durationSeconds` formatted as `M:SS`), number of moves, and highest single-match point value.
- Keep this lightweight — an inline expand/collapse under the tapped row is simplest on mobile; a modal is fine too if it's quicker to build cleanly.

## Regular vs. Special Powers toggle

- A toggle/segmented control at the top of the leaderboard: **Regular** (entries where `powerId === null`) vs **Special Powers** (entries where `powerId !== null`). Filter the displayed list accordingly; keep the underlying `localStorage` data untouched — this is a view-only filter.
- Persist the toggle's last state (e.g. in-memory is fine, or a small `localStorage` key like `mcm.leaderboardView` if it should survive reloads — pick whichever is simpler, either is acceptable).

## Power filter (shown only in Special Powers view)

- When "Special Powers" is selected, show a row of filter chips: "All Powers" plus one chip per entry in the `POWERS` registry (session 10.2), each showing that power's small icon. Selecting a chip narrows the list to `powerId === thatPower.id`; "All Powers" (default) shows every special-powers entry regardless of which power.
- Reuse `generatePowerIcon(id)` from session 10.2 for the chip icons — don't regenerate a separate icon set.

## Per-entry power icon

- In both leaderboard views, each row whose entry has a non-null `powerId` shows a small version of that power's icon next to the name/score (e.g. a 16–20px badge). Regular-view entries (or Special Powers entries with `powerId: null` from before this session shipped) show no icon.

## Files touched

`src/storage/leaderboard.js` (extended entry shape, defensive defaults for old entries), `src/game/ScoreController.js` (`highestMatchPoints` tracking), `src/ui/screens/Landing.js` (toggle, power filter chips, per-entry icon, tap-to-expand detail view), `src/ui/screens/WinScreen.js` or wherever `addScore()` is currently called (session 7) (pass the new fields).

## Done when

- Completing a game (with and without powers) saves a leaderboard entry with correct `durationSeconds`, `moves`, `highestMatchPoints`, and `powerId`.
- Tapping any leaderboard entry reveals date, time taken, moves, and highest match points, formatted legibly.
- The Regular/Special Powers toggle correctly splits entries by whether a power was used.
- In Special Powers view, the per-power filter chips correctly narrow the list, and "All Powers" shows the full special-powers set.
- Entries with a power used show that power's small icon; regular entries show none.
- Old entries saved before this session (missing the new fields) don't break the detail view, toggle, or filters — they just show sensible defaults.
