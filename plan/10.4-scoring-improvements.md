# Session 10.4 — Scoring Improvements (Move-Threshold Multiplier)

## Goal

Reward efficient play: finishing a level within a move threshold applies a bonus multiplier to the final score, revealed with a count-up animation on the win screen.

## Depends on

Session 5.2 (`ScoreController`, running `score`, `moves` tracking), session 7 (win screen), session 10.3 (if done first — `highestMatchPoints`/entry saving should use the *final*, post-multiplier score; order relative to 10.3 doesn't matter much, but make sure whichever lands second reconciles which score value gets saved to the leaderboard).

## Thresholds

Per level, a move-count threshold `T`:

- Easy: `T = 20`
- Medium: `T = 40`
- Hard: `T = 60`

Let `H = T / 2` (half the threshold).

## Multiplier formula

Given `moves` = total moves taken to win:

- **`moves <= H`** → multiplier = **2.00** (flat 2x bonus).
- **`H < moves < T`** → multiplier decreases linearly from just under 2.00 down to 1.00 as `moves` goes from `H` to `T`, computed to 2 decimal places:

  ```
  multiplier = round2( 2 - (moves - H) / (T - H) )
  ```

- **`moves >= T`** → multiplier = **1.00** (no bonus at all — reaching or exceeding the threshold grants nothing extra).

Sanity-check the formula at the boundaries: at `moves = H`, `(moves - H) = 0` → multiplier = 2.00 (matches the flat-2x case, continuous). At `moves = T`, `(moves - H)/(T - H) = 1` → multiplier = 1.00 (matches the no-bonus case, continuous). Good — the piecewise definition is continuous at both boundaries, just clamp explicitly at `<= H` and `>= T` per the spec rather than relying on the formula alone (avoids floating-point edge cases exactly at the boundary).

## Applying the multiplier

- Only applies on an actual **win** (all pairs matched), not on a timeout or a forced loss (session 10.2's Touch of Death 0-score path stays 0 regardless — multiplying zero is a no-op anyway, but don't run the animation/reveal on a non-win ending).
- Compute `finalScore = round( rawScore * multiplier )` where `rawScore` is the accumulated score from `ScoreController` before this bonus (base match points + streak bonuses + any power effects already applied). This multiplier is a final, one-time pass applied once at game end — it does not change how individual matches were scored during play.
- This `finalScore` is what gets saved to the leaderboard (session 5.1/10.3), not the pre-multiplier `rawScore`.

## Win screen animation

- On reaching the win screen, before showing the final saved score:
  1. Briefly display the computed multiplier prominently (e.g. "2.00x Bonus!" or "1.35x Bonus!" — if multiplier is exactly 1.00, it's fine to skip the "Bonus!" framing and just show the raw score with no multiplier callout at all, since there's no bonus to celebrate).
  2. Animate the displayed score counting up from `rawScore` to `finalScore` over a short duration (roughly 1–1.5s), using an easing curve consistent with the rest of the project's hand-rolled tweens (no animation library) — a simple `requestAnimationFrame` loop interpolating the displayed integer value is sufficient.
  3. Leave the finished `finalScore` displayed once the count-up completes.
- If multiplier is 1.00 (no bonus), it's acceptable to skip the count-up entirely and just show `rawScore` (`=== finalScore`) directly — no need to animate a no-op.

## Files touched

`src/game/ScoreController.js` (expose `rawScore`, add `applyMoveThresholdBonus(level, moves)` returning `{ multiplier, finalScore }`), `src/ui/screens/WinScreen.js` (multiplier reveal + count-up animation, save `finalScore` to the leaderboard instead of `rawScore`).

## Done when

- Winning easy in ≤10 moves, medium in ≤20, or hard in ≤30 shows a flat 2.00x bonus.
- Winning at exactly the threshold (20/40/60 respectively) or above shows no bonus (1.00x, `finalScore === rawScore`).
- Winning partway between half-threshold and threshold (e.g. easy at 15 moves) shows a multiplier strictly between 1.00 and 2.00, correct to 2 decimal places per the formula above.
- The win screen visibly counts up from the raw score to the final multiplied score when a bonus applies, and skips the count-up when it doesn't.
- The leaderboard entry saved for that game reflects the final, post-multiplier score.
- A timeout or forced-loss ending never applies or displays this bonus.
